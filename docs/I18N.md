# Internationalisation

The popup and the reminder window ship in English (`en`), French (`fr`) and Arabic (`ar`). The language menu in the header saves the choice under `uiLanguage` in extension storage. Until a choice is saved, the interface follows the browser's UI language when it is one of the three, and English otherwise.

## The string table

`shared/i18n.js` exports one table per language, the storage key, and a few helpers:

```js
export const I18N = {
  en: { appTitle: "Qur'an & Sunnah Companion", play: 'Play', reciterSurahCount: '{count} surahs', ... },
  fr: { appTitle: 'Compagnon du Coran et de la Sunnah', play: 'Lire', ... },
  ar: { appTitle: 'رفيق القرآن والسنة', play: 'تشغيل', ... }
};

translate('fr', 'reciterSurahCount', { count: 12 });  // '12 sourates'
t('play');                                           // in the current language
resolveLang(saved, browserLanguage);                 // 'en' | 'fr' | 'ar'
```

`translate` falls back to English, then to the key itself. `{name}` placeholders are replaced literally.

Every language has the same keys, and every placeholder appears in all three; `npm test` checks both. Notification titles, the reminder window and error messages come from this table too. Surah names come from the Quran.com API: transliterated names in English and French, Arabic names in Arabic.

## Religious content is read-only

Qur'an text and its translation, hadith text, the dhikr Arabic, transliterations and meanings, and the virtue lines are religious content. They live in `shared/dhikr.js` or come from the pinned hadith dataset, never from the string table, and nobody working on the code rewrites or translates them.

Where a dhikr has no line in the interface language, the popup shows the English line rather than a new translation. A virtue has a French line only where one matching the source exists.

If something looks wrong, open an issue that cites the primary source; see `CONTRIBUTING.md`.

UI strings such as labels, buttons and messages can be reworded and translated freely.

## Right-to-left

Choosing Arabic sets `lang="ar"` and `dir="rtl"` on the root element of the popup and the reminder window. The stylesheet uses logical properties (`margin-inline-start`, `inset-inline-end`, `border-block-end` and so on), so the layout mirrors without Arabic-specific rules. Two exceptions are deliberate:

- The playback times keep `direction: ltr`, so `0:23` and `4:51` read in their usual order.
- The arrow on Next dhikr is flipped so it points in the reading direction. The play and pause icons are not flipped.

Arabic text is set in Amiri and never in italics. Every element that holds Arabic carries `lang="ar"` and a direction: the dhikr line is `dir="rtl"`, and hadith text and picker options use `dir="auto"` so mixed Arabic and Latin lines order themselves.

In the Arabic interface the transliteration and English meaning of a dhikr are hidden, and the virtue line is shown in Arabic.

## Adding a language

1. Add a table to `shared/i18n.js` with every key from `en`, keeping each placeholder.
2. Add an `<option>` to the language menu in `shared/popup/index.html`, with its `lang` attribute.
3. For a right-to-left language, extend the `dir` choice in `renderStaticText()` in `shared/popup/popup.js` and in `shared/popup/reminder.js`.
4. Hadith come in the popup's language only where the dataset has both collections in it; other languages fall back to English hadith.
5. Run `npm test` and `npm run sync`, reload both builds, and check every section in the new language.

A language whose dhikr lines or virtues would need a new translation of religious text is shown with the English lines, as French is today.
